# 项目问题与不足记录

本文档记录对项目进行逐项核查后发现的所有问题、简化实现和潜在不足。仅做客观记录，不进行严重程度评级。

---

## 一、认证与鉴权

### 1.1 前端路由守卫集中在 main.js

`frontend/shop-web/src/router.js` 只定义路由表，导航守卫实际集中在 `frontend/shop-web/src/main.js:12-22`。该守卫会拦截 `/admin/*`、`/user/*`、`/pay/*`、`/cart`、`/checkout`、`/feedback`、`/consultations` 等需要登录的路径，并对部分超管页面做前端重定向。权限的最终校验仍依赖后端 `AuthInterceptor` 和 API 返回的 401/403。

### 1.2 Shiro 认证鉴权需手动激活 Profile

`backend/legacy-web/src/main/java/com/example/ecommerce/common/ShiroRealm.java` 和 `ShiroConfig.java` 均标注 `@Profile("shiro")`。默认 Spring Profile 下不加载这两个 Bean，认证鉴权由自定义 `AuthInterceptor` 处理。指导书正文要求“实现认证鉴权功能（可选用 OAuth 或 Shiro 框架）”，因此默认不启用 Shiro 不构成必选项缺失；若需要展示 Shiro 证据，需运行时指定 `--spring.profiles.active=shiro`。

### 1.3 Token 存储在 localStorage

`frontend/shop-web/src/store.js` 将用户 token、userId、nickname、adminId、role 存储在浏览器的 `localStorage` 中，未使用 httpOnly cookie。`frontend/shop-web/src/api.js` 从 localStorage 读取 token 拼接成 `Authorization: Bearer <token>` 请求头。

### 1.4 前端和后端均有角色权限控制

`frontend/shop-web/src/layouts/AdminLayout.vue:74-76` 和 `:84-87` 通过 `session.role === 'SUPER_ADMIN'` 控制菜单项（公告管理、活动通知、用户管理、管理员账号）的可见性。`frontend/shop-web/src/main.js:21` 还会对普通 ADMIN 直接访问 `/admin/users`、`/admin/admins`、`/admin/activity-notices`、`/admin/announcements` 做前端重定向。后端 `AuthInterceptor` 仍是最终权限边界，相关接口会返回 403。

### 1.5 认证令牌无刷新/续期机制

Redis 存储的会话 token 有 12 小时 TTL，到期后用户需重新登录。无自动续期或 refresh token 机制。

### 1.6 关闭浏览器不会主动注销服务端会话

`backend/legacy-web/src/main/java/com/example/ecommerce/controller/AuthController.java:171-176` 注销时删除 Redis 中的 session。前端 `AdminLayout.vue:105-108` 和 `ShopLayout.vue:84-86` 均会在用户点击退出时调用 logout API 并清空本地 session。若用户直接关闭浏览器或标签页，则不会主动调用服务端注销接口，localStorage 中的 token 会保留到用户下次主动退出或 Redis 12 小时 TTL 到期。

## 二、前端/客户端

### 2.1 立即购买流程实现方式

`frontend/shop-web/src/views/ProductDetail.vue:125-138` 的 `buyNow()` 实现方式为：先加入购物车 → 重新请求购物车列表 → 在列表中按 productId 和 specText 匹配刚添加的 cartItem → 存储 cartItemId 到 sessionStorage → 跳转 checkout。在并发或网络延迟场景下存在匹配到其他相同商品/规格的 cartItem 的可能。

### 2.2 管理后台分页实现差异

`AdminProducts.vue`、`AdminOrders.vue`、`AdminUsers.vue`、`AdminReviews.vue` 已通过分页参数请求后端分页数据。少数管理页（如分类、轮播、公告等低数据量配置页）仍一次加载列表后由前端展示，主要适用于课程演示规模数据。

### 2.3 响应式布局覆盖率

存在 26 处 `@media` 查询，主要覆盖以下视图或布局：`HomeView.vue`（1100px/768px/540px）、`ShopLayout.vue`（768px）、`UserLayout.vue`（768px）、`AdminLayout.vue`（768px）、`ProductList.vue`（1100px/768px）、`ProductDetail.vue`（900px）、`CartView.vue`（768px）、`CheckoutView.vue`（900px）、`UserOrders.vue`（768px）、`AdminDashboard.vue`（1100px/600px）、`AdminProfile.vue`（768px）、`UserLogin.vue`（860px）等。指导书要求响应式布局适配手机/电脑，目前已有主要购物流程、个人中心布局、后台外壳和看板断点；部分后台表格页（如 `AdminProducts.vue`、`AdminOrders.vue`、`AdminUsers.vue`、`AdminCategories.vue`、`AdminReviews.vue`、`AdminBanners.vue`、`AdminFeedback.vue`）主要依赖 Element Plus 表格横向滚动和外层布局，页面自身没有独立断点。

### 2.4 管理后台移动端菜单

`AdminLayout.vue:19-21` 有移动端菜单按钮 `mobile-menu-btn`，但仅在 `max-width:768px` 时显示。`AdminLayout.vue:29-37` 的移动端 drawer 与桌面端 aside 使用相同菜单配置，drawer 中菜单项选中后调用 `drawerVisible = false`。

### 2.5 图片加载失败兜底

多处使用内联 SVG data URI 作为图片加载失败的 fallback：`ProductDetail.vue:155`、`CartView.vue:158`、`CheckoutView.vue:119`、`AdminProducts.vue:148`。

### 2.6 加载状态和空状态

项目定义了共享组件 `EmptyState.vue`，在购物车为空、订单为空、搜索无结果等场景下使用。`CartView.vue:105` 使用 `loading` 和 `loadError` 两个状态区分加载中和加载失败。

### 2.7 首页热门商品、轮播和促销数据一致性

`HomeController.java:11` 的 `@Cacheable("home")` 缓存首页数据（banners/hotProducts/newProducts）。商品新增、编辑、删除、导入、下单扣库存/累计销量，以及轮播增删改都会主动清理首页缓存。促销和优惠券数据从 `MarketingController` 独立接口获取（`HomeView.vue` 异步请求 `/marketing/promotions` 和 `/marketing/coupons`），不属于 `home` 缓存内容。

### 2.8 搜索功能的 searchMode 参数仅在 keyword 存在时传递

`frontend/shop-web/src/views/ProductList.vue:92`：`if (filters.value.keyword) params.searchMode = filters.value.searchMode`。如果 keyword 为空，searchMode 参数不传递，后端按默认行为处理。

## 三、后端/API

### 3.1 CORS 配置

多个 Controller 类使用 `@CrossOrigin` 无参数注解，允许所有来源的跨域请求。如 `ProductController.java:17`、`CartController.java:12`、`AuthController.java:17`、`MarketingController.java:9`、`AddressController.java:12`、`ReviewController.java:9`。

### 3.2 订单 API 路径不统一

用户端订单接口在 `/api/orders`（`OrderController.java:28`），管理员订单接口在 `/api/admin/orders`（`OrderController.java:47`）。部分管理操作（如发货）也在 `/api/admin/orders` 下，部分用户操作（如取消/确认收货/支付/退款）在 `/api/orders` 下。

### 3.3 订单创建使用 session 中 userId 而非请求体 userId

`OrderController.java:31` 通过 `CurrentSession.userId(request)` 从 Redis session 获取 userId，而非信任请求体中的 userId。该实现符合指导书对认证鉴权和订单提交流程的要求，也降低了用户伪造他人 userId 下单的风险。

### 3.4 订单列表接口已使用 SQL 分页

`OrderController.java:47-54` 管理员订单列表通过 `searchAdmin(keyword, status, offset, size)` 和 `countAdmin(keyword, status)` 返回分页结果，Mapper XML 使用 SQL `LIMIT/OFFSET`。旧版内存 `subList` 分页已替换。

### 3.5 用户端订单接口兼容分页和旧列表返回

`GET /api/orders` 在传入 `page/size` 时返回 `{ items, total }` 分页数据，`UserOrders.vue` 使用该模式展示订单中心；未传分页参数时仍保留旧的数组返回，兼容现有脚本和旧调用。

### 3.6 密码验证兼容明文密码

`AuthService.java:68-74` 的 `passwordValueMatches()` 方法：若数据库中的密码不以 `$2a$`/`$2b$`/`$2y$`（BCrypt 前缀）开头，则直接用明文比较 `storedPassword.equals(rawPassword)`。这是为了兼容历史明文密码数据。

### 3.7 明文密码自动升级

`AuthService.java:76-82` 的 `migratePlainPasswordIfNeeded()` 方法：若检测到数据库密码为明文，在用户成功登录后自动将其升级为 BCrypt 哈希。升级操作与登录在同一请求中完成。

### 3.8 验证码节流控制

`AuthController.java:51-57` 对同一邮箱+用途在 1 分钟内限制发送一次验证码（`verify:throttle:` + purpose + email key，TTL 1 分钟）。验证码本身 TTL 为 10 分钟。

### 3.9 文件上传校验

`FileController.java` 的 `/api/files/upload` 端点校验文件扩展名（JPG/PNG/GIF/WEBP）和内容类型，限制最大 5MB，保存到 `/uploads/` 目录。文件名使用 UUID 重命名避免冲突。

### 3.10 用户端和管理员端使用不同 Profile 接口

用户端 profile 接口为 `/api/auth/profile`（`AuthController.java:78`），管理员端为 `/api/auth/admin/profile`（`AuthController.java:112`），两套独立接口。

## 四、管理后台

### 4.1 部分管理页面无独立工具栏搜索按钮

`AdminProducts.vue:14` 使用 `el-button type="danger" @click="load"` 作为搜索按钮。部分页面搜索使用 `@keyup.enter` 触发。

### 4.2 管理员个人资料功能较基础

`frontend/shop-web/src/views/AdminProfile.vue` 提供基本资料修改（昵称/邮箱/手机）和密码修改两个区域。`AuthController.java:112-118` 提供相应的 profile 和 password 接口。

### 4.3 用户管理页列表未显示注册时间

`AdminUsers.vue:14-35` 用户表格显示 ID/账号/昵称/邮箱/手机/状态，不含注册时间字段。

### 4.4 管理后台咨询页仅支持留言回复

`frontend/shop-web/src/views/AdminConsultations.vue` 可以查看用户留言、回复留言，但不包含 WebSocket 实时聊天功能。WebSocket 实时聊天仅在用户端 `ConsultationView.vue` 中有客户端实现，`ChatWebSocketHandler` 支持但不强制管理员同时在线。

### 4.5 仪表盘导出与显示不完全对应

`DashboardController.java:13-23` 的 summary 接口返回 userCount/orderCount/salesAmount/productCount/todayOrderCount/todaySalesAmount/salesTrend/hotProducts/orderStatus 共 9 项数据。`:24-32` 的导出接口仅导出前 5 项指标值到 Excel 单 sheet，不含 salesTrend/hotProducts/orderStatus 及对应的图表原始数据。

## 五、订单/支付/退款流程

### 5.1 退款处理仍未恢复库存

`OrderController.java` 的退款申请会校验订单归属、支付状态、订单状态和重复申请；管理员同意退款时会将 `refundStatus` 更新为 `APPROVED`，将 `paymentStatus` 更新为 `REFUNDED`，并插入物流日志。仍未执行以下操作：
- 恢复商品库存
- 恢复秒杀活动库存
- 创建退款金额交易记录

### 5.2 用户退款申请前置条件有限

`OrderController.java` 的退款申请接口检查用户是否拥有订单、订单是否已支付、退款是否已提交/已处理，以及订单状态是否在 `PAID`、`SHIPPED`、`COMPLETED` 内。当前仍未做更细的售后规则，例如收货后可退款时限、部分退款、退款原因和凭证等。

### 5.3 支付为课程模拟实现

指导书正文允许“模拟支付 / 对接支付接口”。`frontend/shop-web/src/views/PayView.vue` 使用硬编码的 SVG 二维码图案和扫描线 CSS 动画模拟扫码支付界面。用户选择支付宝/微信/银联后，点击"确认支付"直接调用 `/api/orders/{id}/pay` 和 `/api/orders/{id}/pay-gateway` 接口。页面标注"课程模拟支付演示"。后端 `/pay` 接口将订单状态改为 `PAID` 并插入物流日志，"支付成功"不依赖任何外部支付网关回调。因此这属于课程允许范围内的模拟实现，而非必选能力缺失。

### 5.4 支付倒计时超时无后端侧限制

`PayView.vue:174-185` 前端 300 秒倒计时，超时后前端隐藏支付界面（`paying.value = false`），但后端无并发超时取消机制。用户在倒计时结束后仍可直接调用 API 完成支付。

### 5.5 订单确认页结算金额计算

`CheckoutView.vue:91-94` 总价和折扣在前端计算：`total` 累加所有商品 subtotal，`discount` 取所选优惠券的 discountAmount（需满足 thresholdAmount），`payable = max(0, total - discount)`。后端 `OrderService.createOrder()` 独立计算并写入数据库。

### 5.6 提交订单后不清空 checkout 相关的 sessionStorage

`CheckoutView.vue:113-114` 在订单提交成功后执行 `sessionStorage.removeItem('checkoutCartItemIds')` 和 `sessionStorage.removeItem('checkoutProductIds')`。若 `submit()` 中 API 调用失败（如 catch 块触发），sessionStorage 不会被清除。

### 5.7 状态变更插入物流日志的粒度

`OrderController.java` 中每次关键操作（支付/发货/确认收货/取消/管理员改状态）都向 `order_logistics` 表插入一条文本记录。日志文本格式为固定中文短语，不含操作人信息。

## 六、商品/分类/库存

### 6.1 商品逻辑删除实现

`ProductController.java:65-69` 的逻辑删除（`DELETE /api/products/admin/{id}`）将商品 `is_on_sale` 设为 0、`stock` 设为 0。物理删除（`DELETE /api/products/admin/{id}/force`）从数据库移除记录。前端 `AdminProducts.vue:128-135` 的删除按钮使用的是逻辑删除端点。

### 6.2 商品导入以 CSV 为主

`ProductController.java` 的 `importCsv` 方法限制 `.csv` 文件，支持引号包裹字段和双引号转义；可识别无 id 表头（`categoryId,name,price,stock,...`）以及商品导出表头（`id,categoryId,name,price,stock,...`）。该导入仍以 CSV 为主，不支持直接导入 Excel 文件。

### 6.3 商品导出字段已覆盖主要编辑字段

`ProductController.java:77-85` 导出 Excel 包含 id/categoryId/name/price/stock/sales/isOnSale/imageUrl/detailHtml/paramsText 等主要字段。导入端可识别导出表头并忽略 id 新增商品，但仍不是“按 id 覆盖更新”的双向同步工具。

### 6.4 库存扣减和销量累计使用 UPDATE WHERE 做并发控制

`OrderService.java` 的 `productMapper.decreaseStock(item.getProductId(), item.getQuantity())` 在 MyBatis Mapper XML 中使用 `UPDATE product SET stock = stock - #{quantity}, sales = sales + #{quantity} WHERE id = #{id} AND stock >= #{quantity}` 模式。返回值 0 表示库存不足，触发异常回滚；成功下单会同步扣库存和累计销量，并清理商品详情/首页缓存。

### 6.5 秒杀库存扣减独立于商品库存扣减

`OrderService.java:42-47` 先执行秒杀库存扣减（`decreaseFlashSaleStock`），再执行普通库存扣减（`decreaseStock`）。两者在同一个 `@Transactional` 方法中但调用顺序固定：秒杀扣减失败抛异常（回滚），普通库存扣减失败也抛异常（回滚，但秒杀库存是否回滚取决于 Mapper SQL 是否也参与了同一事务）。

### 6.6 商品参数以纯文本存储

`Product.java` 的 `paramsText` 和 `detailHtml` 字段以文本形式存储。`AdminProducts.vue:68-69` 编辑表单用 textarea 编辑这两项，无富文本编辑器。

### 6.7 商品规格以键值对动态定义

`ProductSpec` 表通过 `specName`/`specValue` 键值对动态存储每个商品的规格选项（如颜色:红色、颜色:蓝色、尺寸:S）。`MarketingController.java:13` 的 `GET /marketing/specs/{productId}` 返回某商品的所有规格对。前端 `ProductDetail.vue:107` 的 `groupedSpecs` 按 `specName` 分组后用 `el-radio-group` 渲染。

## 七、微服务

### 7.1 微服务使用共享数据库

5 个微服务（auth/catalog/order/admin/gateway）共用同一个 MySQL `ecommerce_minimal` 数据库，而非每个服务独立数据库。服务间通过 HTTP（OpenFeign 或 REST）通信而非消息队列。

### 7.2 订单服务通过 Feign 调用商品服务扣库存

在微服务模式下，`order-service` 通过 OpenFeign `ProductClient` 调用 `product-service` 的 `/internal/products/{id}/deduct-stock` 完成库存扣减。该端点仅在微服务模式下可用，使用了内部路径前缀 `/internal`。

### 7.3 微服务使用 JDBC Template 而非 MyBatis

所有微服务（auth/catalog/order/admin）使用 Spring JdbcTemplate 进行数据访问，不使用 MyBatis。单体应用使用 MyBatis。

### 7.4 网关认证过滤器复制了单体拦截器逻辑

`backend/gateway-service` 中的 `AuthGatewayFilter` 实现了与单体 `AuthInterceptor` 相同的认证逻辑（Redis token 验证、角色检查、请求头注入 `X-User-Id` 和 `X-Role`）。两份代码需独立维护。

### 7.5 微服务中 Feign 调用无熔断/降级

`order-service` 使用 OpenFeign 调用 `product-service` 扣库存，未配置 Hystrix/Sentinel/Resilience4j 熔断器。若 product-service 不可用，order-service 的创建订单请求将直接失败。

### 7.6 Nacos 服务发现配置

微服务通过 Nacos（`nacos:8848`）注册和发现，配置在 `deploy/docker-compose.yml` 和各服务的 `application.yml` 中。Nacos 版本为 2.3.2。

## 八、传统技术模块（Legacy）

### 8.1 Legacy 模块独立隔离

5 个遗产组件集中在 `backend/legacy-web/src/main/java/com/example/ecommerce/legacy/` 包下，不参与主体业务逻辑。`LegacyWebConfig.java` 通过 Spring Boot 的 `ServletRegistrationBean`/`FilterRegistrationBean`/`ServletListenerRegistrationBean` 注册这些组件。

### 8.2 LegacyStatusServlet 提供 HTML 和 JSON 双输出

`LegacyStatusServlet.java:31-37` 根据请求 URI 判断输出格式：`/legacy/status` 输出 HTML，`/legacy/servlet/status` 输出 JSON。HTML 内容在 Java 中用 `StringBuilder` 拼接，而非转发到 JSP。

### 8.3 LegacyStatusController 渲染 JSP

`LegacyStatusController.java:18-25` 使用 Spring MVC `@Controller` + `Model` 将数据注入 JSP 视图 `legacy-status`，由 JSP 脚本块 `<%= %>` 渲染。这与 `LegacyStatusServlet` 的 `/legacy/status` 路径冲突——两者都映射到同一路径，实际谁生效取决于 Spring MVC 的 `@RequestMapping` 与 Servlet 注册的优先级（DispatcherServlet 通常先匹配）。

### 8.4 JSP 视图解析器配置的路径

`LegacyWebConfig.java:33-38` 配置的 JSP ViewResolver 前缀为 `/WEB-INF/jsp/`，JSP 文件实际存在于两个位置：
- `src/main/resources/META-INF/resources/WEB-INF/jsp/legacy-status.jsp`
- `src/main/webapp/WEB-INF/jsp/legacy-status.jsp`

### 8.5 LegacyJdbcDao 与 Spring 同时使用

`LegacyJdbcDao.java` 被标记为 Spring `@Repository` 并通过构造器注入 `DataSource`，但它使用原生 `Connection`/`PreparedStatement`/`ResultSet` 而非 JdbcTemplate。这是一个 Spring 托管的 Bean 中使用原始 JDBC。

### 8.6 LegacyAuditFilter 审计日志存储

`LegacyAuditFilter.java` 使用 `ServletContext` 属性存储审计日志（`ArrayDeque<String>`，上限 50 条），通过 `synchronized (context)` 保证线程安全。审计日志在应用重启后丢失。

## 九、数据库与数据

### 9.1 schema.sql 和 data.sql 初始化路径

`backend/legacy-web/src/main/resources/schema.sql` 定义 21 张表，`data.sql` 包含种子数据。`backend/legacy-web/src/main/resources/application.yml` 中 `spring.sql.init.mode: never`，单体 Spring Boot 默认启动不会自动执行这些 SQL。Docker Compose 通过 MySQL 初始化目录挂载 `schema.sql` 和 `data.sql`，容器首次初始化数据库时会执行这些 SQL。

### 9.2 密码种子数据兼容

`data.sql` 中的种子用户和管理员密码为明文（如 `alice / 123456`、`admin / admin123`、`operator / operator123`）。当前 `AuthService` 兼容明文密码登录，并会在成功登录后自动迁移为 BCrypt 哈希，因此种子数据与当前认证逻辑兼容，但初始 SQL 本身不是 BCrypt 哈希。

### 9.3 订单号生成方式

`OrderService.java:62` 使用 `ORD` + `LocalDateTime.now().format(DateTimeFormatter.ofPattern("yyyyMMddHHmmssSSS"))` 生成订单号。在高并发场景下同一毫秒内可能产生重复订单号。

### 9.4 数据库无显式外键约束

schema.sql 中表之间通过 `user_id`、`product_id`、`order_id` 等字段建立逻辑关联，由应用层维护引用完整性，未使用数据库 FOREIGN KEY 约束。

## 十三、安全

### 13.1 用户敏感信息返回

`AuthController.java:80-81` 的 `/api/auth/profile` 接口返回 `authService.getUser()` 时经 `sanitize()` 方法将 password 字段置为 null。管理员 profile（`AuthController.java:112-113`）调用 `authService.getAdminProfile()`，返回 Map 不含 password。

### 13.2 密码修改需验证原密码

`AuthController.java:90-94` 用户修改密码需提供 `oldPassword`，通过 `AuthService.updatePasswordById()` 验证原密码正确后才更新。管理员修改密码同理（`AuthController.java:106-109`）。

### 13.3 管理员创建时可指定任意角色

`AuthController.java:184-190` 的 `createAdmin` 接口校验 role 必须为 `ADMIN` 或 `SUPER_ADMIN`（使用 Set 白名单）。但接口本身不被 `AuthInterceptor` 中的 `superAdminOnly` 路径列表额外保护——`/api/auth/admin/admins` 已在列表中（`AuthInterceptor.java:51`），该路径仅 SUPER_ADMIN 可访问。

### 13.4 WebSocket 端点无认证

`WebSocketConfig.java:20` 注册 WebSocket handler 到 `/ws/chat/{userId}`，`setAllowedOrigins("*")`。无握手时的 token 验证——任何人知道 userId 即可建立 WebSocket 连接并以该用户身份发送消息。

### 13.5 无 CSRF 保护

未发现 CSRF token 或 SameSite cookie 配置。API 认证依赖 `Authorization: Bearer` 头，浏览器不会自动附加该头，降低了 CSRF 可利用性。

### 13.6 上传文件类型校验的完备性

`FileController.java` 校验文件扩展名和 MIME 类型，允许 JPG/PNG/GIF/WEBP。文件保存到 `/uploads/` 目录并使用 UUID 重命名，避免路径遍历。未对上传文件做病毒扫描或内容校验（如图片是否包含恶意代码）。

### 14.1 消息存储与实时分发

`ChatWebSocketHandler.java:44-50` 将每条 WebSocket 消息保存为一条 `CustomerConsultation` 记录（subject 固定为"在线咨询"，status 为 "PENDING"）。`:53-63` 将消息以 JSON 格式发送给目标用户（若在线）和发送者自己。

`ConsultationView.vue:89` 的 `ws.onclose` 处理中设置 3 秒后自动重连（`setTimeout(connectWebSocket, 3000)`）。无指数退避或最大重试次数限制。

## 十六、其他

### 16.1 购物车 upsert 行为

`CartMapper.java` 的 `upsert` 方法语义：用户对同一 productId + specText 组合再次添加到购物车时，不是增加数量而是更新数量和规格文本。前端 `ProductDetail.vue:121` 调用时传入当前 `quantity` 值，意味着同一用户对同一规格商品多次点击"加入购物车"，购物车中数量为最后一次设置的值。

### 16.2 用户登录仅记住账号

`UserLogin.vue` 仅从 localStorage 读取和保存 `rememberUsername`，不再保存明文密码；页面文案为“记住账号”。登录时会主动清理旧版遗留的 `rememberPassword`。

### 16.3 忘记密码不验证邮箱是否已注册

`ForgotPassword.vue:26-34` 发送验证码时未预先检查邮箱是否已注册。后端 `AuthController.java:73` 在重置密码时做检查，若邮箱未注册返回"邮箱未注册"错误。

### 16.4 优惠券使用后状态

`OrderService.java:69` 在下单后调用 `marketingMapper.useCoupon(userId, couponId)` 标记优惠券已使用。用户优惠券与订单一次绑定，不支持部分使用或退券。

### 16.5 默认头像路径

`AuthController.java:65` 注册时设置默认头像为 `/catalog/avatar-default.svg`。

### 16.6 订单确认页优惠券列表来自用户已领取优惠券

`CheckoutView.vue:104` 调用 `/marketing/coupons/user/{userId}` 获取用户已领取的优惠券列表，而非根据当前订单金额实时计算可用的所有优惠券。

### 16.7 AdminUsers.vue 表格中角色字段

非管理员用户没有 role 字段，`AdminUsers.vue` 表格未显示角色列。用户角色由系统隐式定义为 "USER"（未在 user 表中以字段形式存储）。

### 16.8 商品评论支持分页但无筛选统计

`ReviewController.java` 的 `GET /api/reviews` 在传入 `page/size` 时返回 `{ items, total }` 分页数据，未传分页参数时兼容旧的数组返回。`ProductDetail.vue` 使用分页模式展示评论；当前仍未提供按评分、是否有图、时间范围等维度筛选统计。

### 16.9 邮件发送使用 MailHog

`MailService.java` 通过 Spring Mail 发送 SMTP 邮件，开发环境中邮件被 Docker MailHog 捕获。MailHog Web UI 在 `:18099`（单体模式）或 `:18199`（微服务模式）可查看所有发出的邮件。

### 16.10 Redis 缓存注解使用情况

`@Cacheable` 注解使用场景：
- `ProductController.java:35`：`@Cacheable(value = "productDetail", key = "#id")`
- `HomeController.java:11`：`@Cacheable("home")`

`CacheConfig.java` 配置了 `RedisCacheConfiguration` 默认序列化方式（JSON），未显式配置缓存 TTL。商品新增、编辑、逻辑删除、物理删除、导入和下单扣库存/累计销量会通过 `@CacheEvict(value = {"productDetail", "home"}, allEntries = true)` 主动清理商品详情和首页缓存；轮播增删改会清理首页缓存。促销和优惠券当前不放入 `home` 缓存，仍由独立接口实时查询。

### 16.11 管理后台新建商品时默认图片为空

`AdminProducts.vue:98` 的 `emptyForm()` 默认 `imageUrl: ''`。若新建商品时不上传图片，商品列表和详情页会触发 `imgFallback` 显示 SVG 占位图。

### 16.12 商品详情页的秒杀标签条件

`ProductDetail.vue:114` 的 `flashSale` 检测逻辑为：从 `/marketing/promotions` 返回结果中按 `productId` 匹配且 `promotionType === 'FLASH_SALE'`。前端未再次检查促销起止时间，依赖后端 `MarketingMapper.findPromotions` 只返回 `enabled=1` 且 `now() between start_at and end_at` 的促销数据。

### 16.13 类路径资源与 webapp 目录并存

`backend/legacy-web` 下同时存在 `src/main/resources/META-INF/resources/` 和 `src/main/webapp/` 两个 Web 资源目录，其中 JSP 文件在两个位置都有副本。

### 16.14 无 API 版本号

所有 API 路径以 `/api/` 为前缀，无版本号（如 `/api/v1/`）或版本参数。
