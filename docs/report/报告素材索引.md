## 三、报告素材组织策略

1. “实验内容”部分放表 2-1，快速展示完成范围。
2. “系统设计与实现”部分放 4-5 张设计图，体现系统分析和设计深度。
3. “实验结果与分析”部分每个小模块放 1-2 张截图，不需要把所有截图全部塞进正文。
4. “测试结果”部分放表 5-1 和表 5-2，后面补一句“后端 71 个测试全部通过”。
5. “创新点”部分放 Docker / 微服务截图，支撑拓展创新分。

## 四、建议重点保留的长文段落

如果 Word 篇幅过长需要删减，优先保留以下内容：

1. 4.1-4.4 的架构图、ER 图、登录流程图和购物流程图。
2. 5.1 的测试结果表和 5.3、5.9 的评分点映射表。
3. 5.4 和 5.5 的截图解读段落，尤其是首页、商品详情、购物车、订单、后台看板、商品管理和订单管理。
4. 5.10-5.12 的采分表逐项分析、评分模块洞察和报告表达取舍。
5. 5.13 的部署运行与验证流程，说明系统运行和验证过程。

正文当前已经按“评分点、页面证据、截图解读、测试结果、验证流程”的顺序组织。整理 Word 版本时可以调字号、分页和图片大小，评分表和测试表应尽量保留，因为它们直接对应实验指导书中的完成度要求。
